# SparkJoy レビュー知見 (2026-05-12)

## レビュー対象
- `app.js`
- `index.html`
- `tests/regression.test.mjs`

## 知見サマリ
1. **永続化設定の読み書き処理が重複している**
   - `loadWarn/saveWarn` など、キーだけ異なる同型の関数が多数存在していた。
   - 修正時にデフォルト値・キーの不整合が混入しやすく、メンテナンスコストが上がる。

2. **既定値の単一情報源が分散していた**
   - UI 側 (`index.html`) と JS 側 (`app.js`) の整合はテストされているが、
     JS 側のデフォルト値自体も複数行に分散していた。
   - 値一覧を 1 箇所に寄せることで、変更の影響範囲が明確になる。

3. **回帰テストが実装詳細へ強く依存していた**
   - 既存テストは関数定義文字列に強く依存しており、
     振る舞いを変えないリファクタリングでも壊れやすかった。
   - デフォルト値の実体（設定オブジェクト）を検証する形に寄せると、
     テストは目的（値の整合）を維持したまま柔軟になる。

## 実施したリファクタリング
- `SETTINGS_DEFAULTS` を導入し、Cookie/LocalStorage 併用の数値設定は
  `makeCookieBackedNumberSetting(name)` で生成する方式に統一。
- 既存の `load*/save*` 呼び出し側インターフェイスは維持し、
  画面挙動・保存挙動の互換性を保った。
- 回帰テストは、関数文字列ではなくデフォルト値定義を直接参照する
  マッチに変更し、リファクタ耐性を改善。

## 今後の改善候補
- 設定キー (`LS` / `CK` / `SETTINGS_DEFAULTS`) の定義をスキーマ化し、
  型的にキー漏れを検出できる構造にする。
- 回帰テストに「実際に load/save を評価する軽量ユニット」を追加し、
  正規表現ベース検証を段階的に減らす。
